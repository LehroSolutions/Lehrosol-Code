1 · What Lehrosol Code is

Lehrosol Code is an Electron desktop app built around the LehroSol CLI. They share a model vault and state home (~/.lehro). Discover models, start a local engine, run coding missions in a project, review suggestions, benchmark output, and inspect system status. Local work can run offline once prerequisites are installed; clicking Update contacts GitHub.

LayerMechanism
ActionsThe app invokes the CLI for vault, server, snapshot, and memory actions; the ask bar streams the hands-on code lane.
AwarenessIt reads the CLI's own state files: ~/.lehro/serve.json, ~/.lehro/config.json
EngineThe desktop probes /v1/models and sends /v1/chat/completions requests with the configured authentication key.
DiscoveryA native scanner finds GGUFs on your drives with no config, then registers those folders into the CLI vault (vault add-root) so both tools share one library
Sync (v2.4)The bridge handshakes the CLI version (--version) and speaks the CLI v3.2 quick lane: up, arena, scan, engrams, recommend, doctor, adapters, modes

2 · Install: the LehroSol CLI (prerequisite)

The app is a cockpit over the CLI — install the CLI first. The core is zero-dependency (Node builtins only), so any path works with no build step:

PathCommandWhen to use
npm (global)npm i -g @lehrosolutions/cli@betaYou have Node.js and npm — the standard path
Bunbun install -g @lehrosolutions/cli@betaYou prefer Bun
From sourcegit clone https://github.com/LehroSolutions/lehrosol-cli.gitContributors; the app can point at bin\lehrosol.js directly
# Verify the CLI is healthy:
lehrosol doctor        # read-only health check — never modifies files
lehrosol onboard       # guided first-run: doctor → adapters → recommendation → rehearsal mission

3 · Install: the Lehrosol Code app (dev mode)

Prerequisites: Windows 10/11 x64, Node.js 22.13.0+, and the pinned pnpm@11.15.1 for source builds. Model weights and llama-server are separate prerequisites. No native modules — Microsoft Build Tools are not required.

cd "D:\lehrosol code"
corepack enable pnpm                 # one-time; honors the pinned pnpm 11.15.1
# Alternative if Corepack is unavailable: npm i -g pnpm@11.15.1
pnpm install --frozen-lockfile        # downloads Electron (one-time, needs internet)
pnpm check                           # source and release consistency checks
pnpm start                           # launch the desktop app
pnpm test                            # node --test suite for the bridge & cockpit
pnpm dist                            # build the Windows NSIS installer
Why these settings exist: pnpm-workspace.yaml sets nodeLinker: hoisted for electron-builder and allowBuilds for Electron's binary-download script. Install from the committed frozen lockfile. Environment overrides must be set before launch; the app does not automatically load an .env file.
pnpm start under the hood: it launches Electron through scripts/start.js, which strips pnpm-injected NODE_OPTIONS (e.g. --use-system-ca) that Electron rejects with exit code 9.

4 · Package a Windows installer

pnpm dist builds the Windows x64 NSIS installer in dist/ with the normalized name Lehrosol.Code.Setup.<version>.exe. Run pnpm smoke --packaged to exercise the unpacked application. pnpm release:prepare verifies that filename and bundled help, then writes SHA256SUMS, release.json, and RELEASE-NOTES.md. Tests and synthetic-CLI/engine smoke checks do not replace Windows installation, published CLI pairing, or real-model acceptance. Installers are unsigned unless signing was configured for the build.

6 · Glossary: every control in the cockpit

Agent Stream
Live mission cards for the CLI's code lane: streamed output, status, changed files, retry, and cancel. Missions run in the project you selected.
Ask bar Ctrl /
Run a coding mission from a plain-language goal. New profiles start with Live writes off and send --dryRun. Enable Live writes to permit file changes. Allow run separately permits project-command execution and is off by default. Both choices persist, including existing profiles' preferences.
AI Suggestion
Your local model rewrites the open file; you get a diff card and Apply writes it to disk. No cloud round-trip.
Command palette ⌘ K
Quick access to Quick Start, Rescan Drives, Test Bench, and every other cockpit action.
Engine card / pill
Engine health and Start/Stop controls. Model probes and benchmark calls use the configured API key. Check port/key consistency if an engine appears unreachable.
Files / Search
Project editing and project-wide search over your working folder — the same folder the CLI loop tools operate on.
Memory view
Reads recent ENGRAM records from the paired CLI using engrams --json.
Skills panel
Lists the built-in engineering playbooks the agent can be pointed at, plus reasoning level and resource profile. The playbooks are built into the app (renderer/app.js) — nothing is read from disk at runtime.
Settings
Theme, resource profile, port, API key, auto-start engine, and CLI path (Locate…). Preferences persist in the desktop profile; CLI state and keys also live under Lehro home. Ports must be whole numbers from 1 to 65535. Treat configuration files as sensitive.
System Graph
Live topology: Vault · llama-server · adapter · loop · ENGRAM · web plane. Click nodes to act; one JSON snapshot every 5 s, pausable from the graph header.
Terminal / Events / Output / Engine log
A real shell, a real event feed, and streamed mission output — including the engine's stderr relay (llama-server log lines may appear here; that is the host app surfacing the log, not a CLI failure).
Test Bench ⚖
Pick a model, pick a preset (code / reasoning / summarize / creative / custom), hit Run: the app serves the model if needed, sends the prompt, and records latency, tokens, and tok/s with the full output. Run on all GREAT models races them head-to-head with a leaderboard. Benchmarks carry a background-CPU-load guard — a runaway process can make a 9B model look 6× slower.
Vault ▣
Vault models or native scan results; Rescan drives; add folders to the CLI vault; serve or test any model with one click.
+ New Agent
Choose a GGUF model and serve it through the CLI. A model-server instance is distinct from a coding mission.

7 · Glossary: every concept

Adapter
An agent-CLI integration (Claude Code, Codex, OpenCode, Grok, …) the loop can drive; the app shows readiness from lehrosol adapters --json.
arena
CLI quick-lane race: same prompt across your best local models, tok/s scoreboard with a background-CPU-load validity guard. The Test Bench is the GUI twin of this verb.
dry run
Preview a coding mission with Live writes off (--dryRun). This is the new-profile default; older saved preferences are retained. Terminal commands are independent of this toggle.
ENGRAM
Distilled memory: tiny, project-scoped lessons distilled from old sessions (lehrosol compact) and reused by future runs as field notes. Browse with engrams --json or the Memory view.
GGUF / quant
The single-file local-model format (and its compression level, e.g. Q4_K_M). Prefer Q4_K_M on CPU-only hosts: exotic low-bit quants can be ~2.4× slower per token on AVX2-only CPUs.
HELIX mission
Goal → plan (phase graph: recon → implement → verify, optional harden/document) → execute → verify (Score Agent gate) → adapt (retry → replan → escalate) → report. The Ask bar runs one.
llama-server
The llama.cpp OpenAI-compatible HTTP server that hosts your model. serve start clamps context to 4096 (Qwen-family native 262k contexts can OOM the KV cache) and pins -ngl 0 on integrated-GPU-only machines, where recent builds otherwise auto-enable a slow Vulkan path.
Loop Engine
A CLI harness subsystem for adapter-based scoring and repeated work. The desktop ask bar uses the separate hands-on code lane; do not substitute loop run for that workflow.
Model Vault
The shared model library: scan drives, rate fits (GREAT / TIGHT / NO FIT against real os.freemem() with a 0.85 standby-cache margin), add roots, host directly. Shared between the app and the CLI.
Quick lane
The CLI's one-word commands the app drives: up (zero-to-serving on :7000), arena, ask, code, scan, skills, optimize, missions.
serve.json
~/.lehro/serve.json — the tracked engine state (model, port, API key) both tools read; the app's engine pill and auto-start are built on it.
Score Agent
The grader inside every loop pass: verifies "done" claims against evidence (changed files, tool activity, verification commands) instead of trusting prose.
System Graph planes
The graph's nodes map to real subsystems: Vault (models), llama-server (engine), adapter (agent), loop (harness), ENGRAM (memory), web plane (network-capable surfaces).

Updates and release changes

Click Update in the top bar, Check for updates in Settings or About, or the command-palette action. The app contacts GitHub only when requested, shows the latest published stable version and release changes as text, and excludes drafts and prereleases.

A newer release needs the expected versioned Windows installer and SHA256SUMS before it is offered as an installer update. Open the official download, download the checksum file, compare the installer's SHA-256 against its filename entry, save your work, close the app, and install manually. Code does not update the CLI or restart itself.

No public stable release, offline requests, rate limiting, invalid metadata, and missing assets produce explicit statuses. Retry later or inspect the official Releases page. Local work remains available without an update check.

Editor and suggestion protections

Files with identical basenames have distinct tabs. Unsaved drafts survive tab switches and are protected before close or project change. Saves reject a changed disk version when the expected original content no longer matches. Preserve your draft and reconcile the newer file before retrying.

Truncated large-file reads are read-only previews. A full-file AI rewrite is refused when only partial context fits. Suggestions bind to their source file and original content; switching files or editing the source can invalidate them. Failed saves or Apply retain the draft/proposal rather than reporting success or losing it. Review model output and keep projects backed up.

9 · Troubleshooting

SymptomCause & fix
Electron exits with code 9 under pnpm startpnpm injects NODE_OPTIONS Electron rejects — scripts/start.js already strips it; make sure you start via pnpm start, not electron . directly
Installers won't packageUse the committed frozen lockfile and keep nodeLinker: hoisted/allowBuilds in pnpm-workspace.yaml.
401 "Invalid API Key" floods in the engine logThe app probes /v1/models with the API key saved in Settings. Match the key and port to the running engine; the default key is lehro-local.
Engine "not running" though it isA protected engine rejects a mismatched Settings key with 401/403. Check its actual port and API key, save the matching Settings, and retry the health check.
Benchmarks look impossibly slowCheck background CPU load first — one runaway process skewed a 9B model 6×; the app's benchmarks sample CPU load and flag skewed readings
Model fits but thrashesThe GREAT/TIGHT/NO FIT rating already includes a 0.85 standby-cache margin; if you force a TIGHT model, expect paging — check vault doctor / recommend for smaller quants
corepack enable pnpm unavailablenpm i -g pnpm@11.15.1 — use the repository's pinned version.
Save or Apply refusedPreserve the draft and check permissions, disk changes, truncated preview status, or stale suggestion state. Reopen/reconcile the source before retrying.
Terminal exitedSubmit a new command to start a fresh shell. Inspect any creation error if it cannot restart.
Update check unavailableRetry after connectivity or rate limiting recovers. Drafts and prereleases are intentionally excluded; incomplete release assets do not authorize an installer offer.
